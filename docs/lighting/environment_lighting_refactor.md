# Эталон искусственного освещения (Этап 0)

Фиксация текущего поведения торшера до переработки Environment Lighting System.
Документ — эталон для сравнения после каждого этапа рефакторинга.

## 1. Текущая реализация

### lamp.gd (`scripts/interactibles/lamp.gd`)

Только переключение:

- `interact()` → `is_on = not is_on` → `update_light()`
- `update_light()` → `lamp_light.enabled = is_on; glow_sprite.visible = is_on`
- Начальное состояние: `is_on = false` (свет выключен при загрузке комнаты)

### Lamp.tscn (`scenes/interactibles/Lamp.tscn`)

Корень `Lamp` (Area2D). Ключевые узлы и параметры:

| Узел | Параметры |
| ---- | --------- |
| `Sprite2D` | `Lamp.png`, offset `(-181, -585)`, scale `(0.356, 0.379)`, not centered |
| `PointLight2D` | position `(0, -504)` |
| | color `Color(0.5397, 0.4482, 0.1623)` — тёплый |
| | energy `1.77` |
| | texture: GradientTexture2D 768×768, radial (`fill = 1`), from `(0.5, 0.5)` |
| | gradient: offset 0.185 → `RGB(0.742, 0.724, ~0)`, offset 1.0 → белый с alpha 0 |
| | `texture_scale = 2.0` (эффективный радиус ≈ 768 px) |
| | `shadow_enabled = true` |
| | `shadow_item_cull_mask = 2` (слой 2) |
| | `range_layer/min/max` — значения по умолчанию |
| `GlowSprite` | Sprite2D **без текстуры** (свечение плафона не реализовано) |
| `StaticBody2D` | коллизия корпуса (физика) |
| `LightDepthPoint` | Marker2D `(0, -41)` — условная глубина для стола и SurfaceSpot |
| `FlashlightShadowCaster` | 3 скрытых Polygon2D: `Lampshade`, `Pole`, `Base` — силуэт для 2.5D-теней фонарика |
| `InteractionLabel` | «Включить торшер» |

## 2. Зависимости, которые нельзя сломать

### desk.gd

- `lamp_reference: Area2D` назначен в bedroom.tscn (`../Lamp`)
- Ищет `PointLight2D` по строковому пути `"PointLight2D"` — **получает, но не использует** (мёртвый код)
- `update_occluder()` каждый кадр в `_process`: по `LightDepthPoint.global_position.y` против `global_position.y` включает `OccluderFront` либо `OccluderBack`
- **Требование:** после рефакторинга торшер обязан сохранять узлы с именами `LightDepthPoint` (до Этапа 4)

### surface_spot.gd (фонарик)

- Использует от торшера только `FlashlightShadowCaster` (полигоны) и `LightDepthPoint`
- Не читает `PointLight2D` торшера — рефакторинг искусственного света на фонарик не влияет
- **Требование:** выключенный торшер продолжает отбрасывать тень от фонарика

### hidden_inscription.gd

- Определяет обнаружение через duck-typed вызов `surface_spot.get_light_strength_at()`
- **Правило:** надписи реагируют только на фонарик. `ArtificialLightSource` не должен предоставлять метод `get_light_strength_at`, чтобы duck-typing случайно не нашёл совпадение.

## 3. Контрольные сценарии (проверять после каждого этапа)

Запускать сцену `scenes/levels/bedroom.tscn`:

1. **Выключенный торшер при загрузке.** Комната тёмная (`CanvasModulate 0.31/0.32/0.40`), торшер не светит, силуэт от фонарика есть.
2. **Включение.** Пятно тёплого света у плафона (позиция чуть выше плафона), радиус застилает стол и часть пола, тень от стола падает в сторону от лампы.
3. **Тени фонарика при включенном торшере.** Силуэт торшера (абажур, стойка, база) отбрасывает 2.5D-тень.
4. **Выключение.** Свет гаснет мгновенно (текущее поведение — без фейда), `GlowSprite` скрыт.
5. **Скрытые надписи.** При включенном торшере надписи НЕ проявляются (только от фонарика).
6. **Ящики стола.** Переключение окклюдеров не меняется (торшер один, справа/сзади — задний окклюдер).

Контрольные скриншоты снимаются вручную в Godot до начала Этапа 3:
`Фонарик выключен + торшер выключен`, `торшер включён`, `фонарик включён + торшер включён` (пятно на столе), `фонарик на торшер (силуэт)`.

## 4. Находка Этапа 1: маски теней в Godot 4.7

Проверено контрольными запусками (Godot 4.7.2, GL Compatibility и Vulkan):

- Стандартные тени Godot работают только при паре
  «`shadow_item_cull_mask = 1` у света + `occluder_light_mask = 1` у
  окклюдера» (значения по умолчанию).
- **Любой** `shadow_item_cull_mask != 1` молча убирает тени: проверены
  пары «2/2» при Range = 1 и Range = 3, «2» у света с окклюдером на
  слое 1, окклюдер с `light_mask = 2` — тени нет во всех вариантах.
  Похоже на движковую регрессию/ограничение 4.7 — перепроверить при
  обновлении Godot.
- Следствие: раздача окклюдеров источникам по маскам НЕВОЗМОЖНА.
  Выбор «передний/задний окклюдер» делается событийной логикой
  (`desk.gd`), а не масками.
- Следствие для спальни: у старых `PointLight2D` торшера и окклюдеров
  стола стоял слой 2 — стандартные тени от торшера не отображались
  никогда (видимые «тени стола» давали 2.5D-проекции `SurfaceSpot`
  от фонарика). Теперь всё переведено на слой 1.
- Удаление/пересохранение файлов в редакторе: Godot перезаписывает
  `.tscn` и `.tres` (добавляет `uid`/`unique_id`) и может **потерять
  свойства** — при правке текстовых ресурсов держать сцену закрытой.

## 6. Статус этапов

- **Этап 0 — выполнен.** Эталон в разделах 1–3.
- **Этап 1 — выполнен.** `LightProfile`, `ArtificialLightSource`, тест-сцена
  `scenes/debug/light_source_test.tscn`, находка про маски (раздел 4).
- **Этап 2 — выполнен.** `EnvironmentLightingManager`
  (`scripts/lighting/environment/environment_lighting_manager.gd`):
  реестр источников (автосбор из поддерева комнаты + register/unregister
  для спавна), группы `ELECTRIC / DECORATIVE / EMERGENCY` (битовая маска,
  синхронна с `LightProfile.groups`), команды: `turn_on/off_all`,
  `turn_on/off_group`, `set_energy_factor_all/group`, сигналы
  `source_registered/unregistered`. Per-room узел, не autoload.
  В тест-сцене: `Space` — все через менеджер, `P` — отключение
  электричества (свеча горит), `O` — включить все, стрелки — приглушение.
- **Этап 3 — выполнен.** Торшер переведён на новую систему:
  - `Lamp.tscn`: узлы `PointLight2D` и `GlowSprite` удалены, вместо них
    компонент `ArtificialLightSource` с профилем `floor_lamp_profile.tres`
    (параметры света 1:1 из эталона, свечение плафона пока alpha 0);
  - `lamp.gd`: только `light_source.toggle()` + подсказка
    «Включить/Выключить торшер», метод `is_lit()` для будущих проверок;
  - `bedroom.tscn`: добавлен узел `EnvironmentLighting` (менеджер,
    автосбор по корню комнаты);
  - `desk.gd`: удалена мёртвая зависимость от `PointLight2D` (окклюдеры
    по-прежнему переключаются по `LightDepthPoint`);
  - `FlashlightShadowCaster` и `LightDepthPoint` сохранены — фонарик
    и `SurfaceSpot` работают без изменений;
  - проверено автотестом-пробником: менеджер видит 1 источник,
    включение/выключение работают, кадры до/после совпадают с эталоном.
  Осталось сверить вручную с эталоном (раздел 3) и принимать решение
  по свечению плафона (emissive).
- **Этап 4 — выполнен.** Тени и окклюдеры стола:
  - `Desk.tscn`: окклюдеры переведены с `occluder_light_mask = 2` на
    слой 1 (при старом значении стандартные тени не строились вовсе);
  - `desk.gd`: убрана покадровая авторотация из `_process`; стол
    подключается к источникам из группы `artificial_light_sources`
    (источник добавляет себя в группу в `_enter_tree`) и обновляет
    окклюдеры по сигналу `state_changed`;
  - учитываются только ВКЛЮЧЁННЫЕ источники — выключенный торшер не
    отбрасывает тень на стол;
  - сторона выбирается по `LightDepthPoint` владельца источника;
    при источниках с разных сторон одновременно — передний окклюдер
    и `push_warning` (ограничение движка, раздел 4);
  - убран `lamp_reference` из `desk.gd` и `bedroom.tscn` (мёртвая связь);
  - `ArtificialLightSource` добавляет `range_item_cull_mask` без
    изменений: экспериментально подтверждено, что Range-маска не влияет
    на построение теней.
- **Этап 5 — выполнен.** Типы света и эффекты:
  - `LightProfile.behavior`: `CONSTANT` (без анимации, `_process`
    выключен), `FLICKER` (скачки яркости — свеча, неисправная лампа),
    `PULSE` (синусоида — аварийный свет); `flicker_speed` — смены/сек
    для FLICKER и циклов/сек для PULSE;
  - свечение плафона (`EmissiveVisual`) модулируется вместе со светом;
  - анимированные режимы не используют твин (анимация сама управляет
    энергией);
  - новые профили: `faulty_bulb_profile.tres` (холодная неисправная
    лампа, сильное редкое мерцание, группа «Электричество»),
    `emergency_profile.tres` (красный пульсирующий, группа «Аварийное»);
  - тест-сцена: третий источник `EmergencySource`, клавиша `3`,
    `P` гасит только группу «Электричество» (свеча и аварийный горят).
  Направленный свет (DirectionalLight2D) в подсистему не входит —
  это отдельный тип узла Godot, при необходимости добавим отдельно.

## 7. Целевая архитектура (сводка)- `LightProfile` (Resource, `scripts/lighting/environment/light_profile.gd`) — настройки: цвет, энергия, радиус, текстура пятна, тени, поведение (фейд/мерцание), группы. Read-only в рантайме; всё изменяемое состояние — в источнике.
- `ArtificialLightSource` (Node2D, `scripts/lighting/environment/artificial_light_source.gd`) — владеет `PointLight2D`, применяет профиль, включение/выключение/фейд/мерцание, сигналы. Не предоставляет `get_light_strength_at`.
- `EnvironmentLightingManager` (Этап 2, per-room, не autoload) — реестр источников, группы, команды.
- Игровые объекты (торшер и будущие светильники) — содержат источник как компонент.

Этапы: 0 — эталон (этот документ) → 1 — источник + профиль + тест-сцена → 2 — менеджер → 3 — перенос торшера → 4 — тени/окклюдеры стола → 5 — типы света и эффекты → 6 — сюжет и сохранение → 7 — регресс.
